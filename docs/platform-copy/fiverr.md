## Gig 1 — Laravel API development

```
Title: I will build a clean, documented Laravel REST API for your app

Category: Programming & Tech → Web Programming → Backend Development
```

**Description**

```
A Laravel API that your web or mobile team can build against without guessing.

I build Laravel APIs in production every day — including the backend behind a Flutter attendance app
and the API layer of an enterprise supply chain platform. That means:

• Resource controllers with clear, versioned routes
• JWT or Sanctum authentication and a permission model that actually matches your roles
• Validation, pagination, filtering and consistent error responses
• Migrations and seeders so the schema is reproducible
• OpenAPI/Swagger documentation, or a Postman collection
• Tests on the endpoints that matter

Whether you need a new API from scratch, extra endpoints on an existing one, or a messy API cleaned
```

| Tier | Scope |
| --- | --- |

```
Q: Will you deploy it?
A: Deployment is a separate gig, but I can provide the Docker setup and the deploy steps.
```

## Gig 3 — Laravel bug fixes and rescue

```
Title: I will fix Laravel bugs, upgrade packages and rescue a stuck PHP project

Category: Programming & Tech → Web Programming → Bug Fixes
```

**Description**

```
Your Laravel app is broken, slow, or stuck mid-upgrade — and you need someone who reads code before
changing it.

I have inherited more codebases than I have started, so I know the drill: read the existing code,
find the actual cause, change as little as the fix requires, and leave the project better documented
than I found it.

Typical jobs:
• "This page throws a 500" — trace and fix, with the root cause explained
• "Package upgrade broke the admin" — upgrade, resolve conflicts, test the critical paths
• "It is slow" — query and N+1 analysis, indexes, caching where it helps
• "The previous developer disappeared" — a module built or finished on an unfamiliar codebase
• "The API does not return the right data" — relationship, scoping or validation bugs

I work on Laravel 8–12, PHP 8+, MySQL and PostgreSQL. I will always tell you when a rewrite is
cheaper than a fix — and when it is not.
```

**Packages**

| Tier | Scope |
| --- | --- |
| Basic | One bug, root-caused and fixed, with a short explanation |
| Standard | Up to 3 bugs, or one package upgrade with verification |
| Premium | A rescue session: audit of the failing area, fixes, and a written summary of what to watch |

**FAQ**

```
Q: Can you access my repo/server?
A: Yes — repo access is enough for most work. For server-side issues I will need SSH or a staging
copy.

Q: Do you sign NDAs?
A: Yes.

Q: What if the bug is in a package, not your code?
A: I will find that out and tell you — and I will either patch around it safely or recommend the
right fix upstream.
```

## Pricing guardrails

- Do not sell "unlimited revisions". Cap at 2 rounds for Basic, 3 for Standard.
- For anything touching an ERP module, quote from a scope call, not from the gig tier.
- Keep delivery time honest: gigs that overpromise speed attract the wrong buyers.
